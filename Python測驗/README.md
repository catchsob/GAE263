# Log 解析
處理 JSON 格式的 log 檔，針對各服務計算不同嚴重等級 log 次數，共計 3 個任務

## 任務 1  
**針對每個服務 (服務名稱記錄在 "service_name") 計算並輸出各種嚴重等級(嚴重等級記錄在 "severity") log 發生的次數，輸出格式不限，順序不限**

### 輸出內容
```text
pauca ERROR: 26/ INFO: 23/ NOTICE: 0/ WARNING: 2
myca  ERROR:  0/ INFO:  3/ NOTICE: 0/ WARNING: 0
wt    ERROR: 36/ INFO: 53/ NOTICE: 1/ WARNING: 0
```

## 任務 2  
**將任務 1 程式包裝為 function，能夠指定待處理的 log 檔名，並輸出所有服務各種嚴重等級次數**

### 限制
> 1. 輸出格式須遵循下列輸出內容範例 (尤其是對齊與空白)，其中嚴重等級依字母順序，但服務名稱無順序
> 2. Function 須防呆 & 容錯

### 輸出內容
```text
pauca ERROR: 26/ INFO: 23/ NOTICE: 0/ WARNING: 2
myca  ERROR:  0/ INFO:  3/ NOTICE: 0/ WARNING: 0
wt    ERROR: 36/ INFO: 53/ NOTICE: 1/ WARNING: 0
```

## 任務 3  
**強化任務 2 function，除能夠指定待處理的 log 檔名，預設情況下能夠輸出所有服務各種嚴重等級次數，亦能夠僅輸出指定服務的各種嚴重等級次數**

### 限制
> 1. 輸出格式須遵循下列輸出內容範例 (尤其是對齊與空白)，其中嚴重等級依字母順序，但服務名稱無順序
> 2. Function 須防呆 & 容錯

### 輸出內容
```text
wt ERROR: 36/ INFO: 53/ NOTICE: 1
```

## 注意事項
> 1. 只能使用 json 套件，禁用其他套件，違者總分 0 分  
> 2. 注意 "service_name" 非 "serviceName"
> 3. 服務名稱與嚴重等級不得寫死
> 4. 注意任務 2 & 任務 3 要求的包裝方式為 function，若包裝為 class 則該任務 0 分
> 5. 評分時將以同規格的其他服務 log 檔驗證，須注意輸出數據正確性與輸出整齊度
> 6. 禁止 vibe coding，違者總分 0 分
